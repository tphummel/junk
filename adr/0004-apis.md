# 0004: How APIs are built

- Status: Accepted
- Date: 2026-11-14

## Context

All APIs are routes in one [Hono](https://hono.dev) router (`api/index.ts`) under `/api/*`; [ADR 0005](0005-cloudflare-workers-deployment.md) covers deployment. The first routes (`health`, `golden-angle-palette`) established these conventions so agent sessions add routes consistently.

## Decision

1. **One file per API.** `api/<name>.ts` default-exports a Hono sub-app with routes relative to its mount point. `<name>` is lowercase kebab-case, and the same as the paired `web/<name>/` if there is one.
2. **Register it** in `api/index.ts`: one import and one `app.route("/api/<name>", sub)` line, in alphabetical order. Unknown paths get the global JSON 404.
3. **JSON in, JSON out.** Validate all input. Bad input returns `400` with `{ "error": "<message>" }` saying what to use instead. Never return stack traces.
4. **HTTP behavior is chosen per API:** `GET` for read-only calls; `Cache-Control: public` only when the response is deterministic; CORS (`hono/cors`) only when other origins' browsers should call it.
5. **Public by default.** There is no authentication. Anything that must be protected needs its own ADR first.
6. **Tests** in `api/<name>.test.mjs` using `node:test` and `app.request()`, with no network: the happy path, every validation error, and any headers the API promises.
7. **Shared logic.** Code used by both a page and its API is a plain ES module under `web/<name>/` that the API imports ([ADR 0002](0002-no-web-build-step.md)).
8. **Bindings and secrets** are read from `c.env`; how they are declared and isolated is in [ADR 0005](0005-cloudflare-workers-deployment.md).

The procedure, templates and checklist for bindings are in the [`new-api` skill](../skill/new-api/SKILL.md).

## Consequences

- Adding an API is one file, one test file and one registry line.
- `api/index.ts` is a registry that parallel sessions will conflict on; keep both entries.
- Every API is public, including any that write data.

## Alternatives considered

- **Colocating each API in its project folder.** A flat `api/` keeps the registry and tests in one place.
- **A plain `fetch` handler with path matching.** Fewer dependencies, but Hono provides sub-routers, params and middleware.

## Open (needs its own ADR when first needed)

- **Storage.** Which of KV, D1, R2 and Durable Objects, and whether APIs share a binding with per-API prefixes or get dedicated ones. A shared binding lets any API read any other's data.
- **Authentication** for any API that should not be public.
